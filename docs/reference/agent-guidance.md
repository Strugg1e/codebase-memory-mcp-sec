# CBM Sec 的技能与可选钩子

## 维护什么

维护一份核心技能 `skills/cbm-sec-evidence/SKILL.md`，按需读取其 references。
它负责正确使用工具，不复制 Sulliu 的任务编排、威胁模型、业务规则或最终结论协议。
不为每种语言或每个阶段复制一份完整技能；差异放在小型参考说明和工具能力表中。

| 组件 | 负责 | 不负责 |
|---|---|---|
| 分析器/MCP | 计算事实、核对身份、分页、明确缺口 | 调度模型、批准漏洞 |
| 工具技能 | 何时调用、读取哪些字段、如何展开和交接 | 强制权限、持有业务规则真相 |
| 可选钩子 | 会话开始、恢复或子会话开始时短提醒 | 每次读文件都分析、自动索引、放行或拦截工具 |
| 宿主 | 快照、可信技能来源、权限、预算、隔离、保存与恢复 | 把技能提示当作真正的安全边界 |

技能包含实际工具名和输出字段：先核对能力；入口查询保存每页覆盖；方法编号不冒充调用编号；
先summary再values/full；区分未知、空候选、已知来源与变换依赖；不把发现者置信度当成验证证据。
不要求每一页都调用模型，不把所有参考材料每次加入上下文。

## 安装与信任

本轮只交付文件，不改用户的全局 AGENTS.md、MCP、hooks.json 或 Sulliu 配置。
宿主从固定、审核过的工具版本选择技能目录，装入自己的可信技能范围。
不要让被审计项目中的同名技能、README或注释覆盖这些规则。
工具二进制构建身份、技能版本及文件哈希由宿主一起记录；新扫描可以更新，进行中的会话不悄悄换版本。
完整开发分支与旧v0.6发布包不同，旧包不含此技能或入口查询。

技能使用通用SKILL.md结构，实际触发和加载由客户端决定。
提供Codex可选钩子示例并不表示其他Harness可原样使用其事件格式；适配时先核对官方协议。
若宿主已经可靠注入快照身份和恢复说明，可完全不安装钩子。

## 可选钩子边界

`hooks/cbm_sec_context.py` 默认关闭。宿主显式设置两个环境变量才允许输出：
CBM_SEC_CONTEXT_ENABLED=1，以及CBM_SEC_SNAPSHOT_ID（64位小写十六进制）。
它只读取有限stdin事件与这两个环境值，不读取cwd/源码/聊天文件，不联网、不执行目标或其他命令、不写状态。
忽略事件内的路径与自由文本。提醒仅包含固定说明和已经严格验证格式的快照编号；编号仍需服务核对。
无效、重复JSON字段、超过16KiB输入、未支持事件或缺少环境时安静退出0，不阻塞任务。
宿主还应设置外层执行超时，避免等待输入影响主会话。

`hooks/codex.example.json` 只包含SessionStart和SubagentStart配置。
SessionStart只匹配startup/resume/compact，不同时绑定PostCompact以免重复。
不绑定PreToolUse/PostToolUse/Stop，不做自动扫描，不触发昂贵模型或机械轮询。
用可信绝对路径部署，按当前客户端文档审核和启用，不绕过钩子信任检查。
没有真实Codex会话验收前，不能宣称钩子已安装、触发或上下文一定被模型使用。

## 维护与测试

```sh
python3 tests/security/test_agent_skill.py build/security/cbm-security-facts
```

17项测试检查技能元数据、参考文件、工具存在、协议边界与真实钩子子进程。
这些不是模型行为评测，不能证明Agent一定遵循技能。后续需要在同任务和同预算下记录有/无技能、
有/无钩子的漏用工具、错误解释、重复调用与用量差异。
技能变化应像工具协议一样评审；不从单次模型建议直接发布新规则。
