# 消费端接入与故障回放

本配套是一个可运行的宿主接入示例，不是新增 MCP 工具、任务调度器或真实 Agent 评测。它复用 `demo_flow.Client`、现有结构/关系查询及离线导出器。不得把本实验自动提升为现有预览版本的发布门槛。

## 运行

```sh
make -f Makefile.security
python3 security/demo_consumer.py --mcp build/security/cbm-security-mcp \
  --output-dir build/consumer-example
python3 tests/security/test_consumer_replay.py build/security/cbm-security-facts
```

输出目录必须不存在。只分析仓库固定文本，运行可信分析器及离线复核进程，不执行 Java、SQL、模型、网络或被审计项目。示例沿用 POSIX 管道和不可覆盖的文件写入；平台支持以实际验证记录为准。

正常完成输出 `controlled_replay_passed`，这表示脚本的预期行为通过，不表示漏洞成立或模型理解正确。失败退出 2，标准输出不报告成功；已落盘的记录保留用于排查，不自动删除或改写。

## 三种身份与三类状态

| 名称 | 意义 |
|---|---|
| `invocation_id` | 宿主的一次调用身份，每次尝试不同；不是源码 `call_id`，也不是 JSON-RPC 序号 |
| `query_id` / `context_id` | 工具的查询或操作身份，从真实返回中保留 |
| `response_sha256` | 本次完整工具返回经规范 JSON 保存后的字节哈希 |
| `capture_sha256` | 既有单操作捕获格式的哈希，不与上述返回哈希混用 |
| `snapshot_id` / `build_id` | 本实例固定的源码和分析程序身份 |
| `task_id` / `attempt` | 示例宿主的任务及尝试，不能从源码或返回内容决定 |

| 维度 | 行为 |
|---|---|
| 请求执行 | `succeeded`、`tool_error`、`timed_out`、`transport_error`、`invalid_response`、`persistence_error` 分开记录 |
| 内容交付 | 短预览始终为 `preview_only`；即使预览碰巧包含全部内容，也不代替显式补读 |
| 宿主接纳 | 补读前为 `needs_full_read`；换尝试后旧结果为 `rejected_stale_attempt`；取消后为 `rejected_cancelled` |

`full_payload_available` 只说明示例消费者已按原哈希取得该次完整消息。若该消息本来是 summary，补读仍然只得到完整的 summary，必须另按 `full_request` 查询原操作。它也不证明模型看到了全文、理解正确或分析完整。查询的条件、`gaps`、`coverage`、`frontiers` 与 `truncated` 仍在原始结果中，`semantic_completeness` 一律不由示例推断。

`Client.rpc` 已解析 JSON-RPC；保存文件是完整工具结果的规范 JSON，包含文本和结构化两种载荷，不声称保存了原始网络字节。文本和结构化内容必须一致，布尔值与整数不等同。结果先落盘，再进入可用状态。调用参数也按值复制并单独保存，后续修改调用方字典不能改变旧记录。

## 实际路径与故障边界

示例先分页列资源，保留每页完整返回；空页有游标就继续，检查查询身份、任务偏移连续性和游标进度。达到页数上限时保留已有页面及下一次参数，报告 `page_budget_exhausted`，不把它包装成枚举完成。解析/工具错误不会变成成功的空清单。原始声明、检查尝试与覆盖范围不跨页合并、去重或丢弃。

选中操作后，按真实请求取得概览，再展开完整操作。另存普通实参查询及其深度停止结果，并关联单操作捕获。完整自动搜索返回与操作证据包分别保存；本示例没有新增整条搜索的离线语义验证器。导出器仍只核对已有单操作完整结果的源码引用。

| 场景 | 实验内容与限制 |
|---|---|
| 短预览看不到后面的检查调用 | 真实源码返回在消费端截取 256 字节，补读完整消息后看到 `validateTenant`；只证明文字存在，不证明检查有效 |
| 已知路径和未知返回并存 | 使用真实查询，保存全部已知路径和未知项，不只摘取成功路径 |
| 深度预算停止 | 正常返回仍保留 `trace_depth_limit` 和 `truncated=true`，不形成否定结论 |
| 工具错误 | 向真实 MCP 发送一个无效实参位置，保存实际错误载荷 |
| 迟到返回 | 暂存一个真实返回，在宿主切换尝试后交付；这是明确注入的交付顺序，不声称服务器发生并发或网络延迟 |
| 超时 | 专用夹具注入 `TimeoutError`，不声称实际 MCP 超时；已完成/失败调用拒绝再次交付 |

超时或传输错误后，示例将该连接标为不可再调用。`new_attempt` 不会解除这一状态，必须由宿主关闭旧进程并创建、核对新连接，不能在旧管道上把残留返回当作重试结果。现有演示客户端的通用 `RuntimeError` 记为 `transport_error`，不猜测其具体原因；只有明确的超时异常才记为 `timed_out`。示例不自动重试、不恢复检查点、不在后台工作。

演示最后故意取消宿主任务，然后退出分析进程，才运行既有离线导出与复核。此时源码引用仍可能正确，但该任务的结果已不能被当前宿主接纳。这是有意验证“证据完整性”与“任务有效性”的区别。

## 文件与测量

输出包含固定快照、启动身份、各次请求和完整工具结果、单操作捕获、证据包及 `RECEIPT.json`。新文件不可覆盖，数据文件权限为 0600，目录为 0700。输入二进制和目录及其祖先目录由可信宿主选择。源码路径只作为快照标识，不用于读取宿主文件。

示例最多 128 次调用；单工具保存结果最多 8 MiB，累计工具结果 32 MiB；每次分页默认 32 页，上限 64。超过示例预算即停止，不删减结果后报告成功。这些是宿主示例限额，不是分析器新上限。

回执记录实际耗时、保存载荷字节数和客户端读取的响应字节数。保存载荷包含文本/结构化双编码，而短预览仅是结构化对象的前缀；两者不能直接算成节省比例。没有测量模型实际输入、Token、前缀缓存或漏洞召回，也没有普通读码与 Agent 的成对对照。

哈希来自可信任务记录才有核验意义；同目录回执不是数字签名、生产者认证或持久任务恢复机制。源码片段和完整响应可能包含秘密，不能自动公开。字段标记不能代替宿主权限和消息隔离；源码始终为不可信数据。
