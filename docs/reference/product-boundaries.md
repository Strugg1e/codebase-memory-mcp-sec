# CBM Sec 产品边界

适用：0.9 开发版。本文说明职责，不代表未实现的目标能力已经交付。

CBM Sec 是一个程序证据服务，不是漏洞扫描编排器，也不是 Agent 运行时。

| 层次 | 责任 | 当前实现 |
|---|---|---|
| 源码身份 | 宿主选定范围；工具校验文件与包哈希 | 固定源码包、精确位置与分析编号 |
| 结构导航 | 原版 CBM 或宿主搜索提供候选 | 安全工具不读取原版图数据库；新增位置交接接口 |
| 程序关系 | CBM Sec 在支持范围内计算依赖 | 语法事实、Java 局部/多跳/返回摘要、MyBatis 材料 |
| 业务含义 | Agent 提出解释；引用代码与业务资料 | 不是本工具中的确定事实库 |
| 安全要求 | 宿主管理人工确认的规则、范围和例外 | 工具不从目标配置自动加载或批准规则 |
| 扫描与结论 | 宿主运行调查、反证、报告和恢复 | 不在本项目复制一套 Sulliu |

## 相同 Harness，不同任务配置

程序材料可以共用；会话意图、权限与预算按任务配置。
索引准备由普通程序负责。侦查先看结构和小视图；验证围绕一个中性问题按需取证。
不要把发现者的置信度或完整聊天记录当成验证证据，也不要用工具缺失阻止源码调查。

宿主必须负责源码只读挂载、进程隔离、总时间/内存/并发限制、取消与清理。
MCP 的只读标注仅表达用途，不提供操作系统级隔离。静态调查与动态验证应使用不同权限配置。
本版不安装全局 AGENTS.md、不设置客户端钩子、不修改 Codex、Pi 或其他客户端配置。

## 数据边界

底层源码事实、程序推导、人工上下文、模型解释和安全结论应分层保存。
一次模型解释不能写回本次不可变源码证据，目标仓库内的指令也不能成为扫描策略。
位置匹配只能核对当前源码，不能证明外部图的构建来源、调用边或运行时分派。
业务规则缺失时允许保留未知，不以现有实现反推必须遵守的规则。

## 评价边界

分别记录事实正确性、有效范围、完整性缺口、协议可靠性、返回字节和程序耗时。
只有同模型、同快照、同预算的真实工作流对照，才能讨论召回、准确率或模型成本变化。
当前示例只验证协议交接和视图保真，不提供实际 Sulliu/Codex A/B 结果。

## 开发边界

本版主要整理产品入口和接口，没有扩大污点求解范围。
分析核心继续共用，不按侦查/验证角色复制引擎。先维持 fork，待依赖接口清楚后再决定拆仓库。
已发布标签不移动。主分支门禁、贡献署名和许可证独立于专项测试，不能用开发预览取代。
