# 产品与架构

CBM Sec 是程序分析与证据服务，不是独立的 AI 漏洞扫描平台。它服务证据驱动审计的两套循环：提出有仓库依据的威胁命题；查找支持或推翻命题的材料。

## 数据怎样流动

```text
宿主固定源码和分析范围
          ↓
语法事实与框架声明
          ↓
入口／调用现场／局部值流／返回摘要／模板／安全配置
          ↓
按问题组织有界查询结果及源码引用
          ↓
Agent 提出假设、补证据和检查反证
          ↓
宿主保存裁决、报告和未完成任务
```

原版 CBM 的结构导航可帮助寻找位置，但当前安全服务没有直接导入原版持久化图。位置对齐也不等于证明原调用边正确。

## 四类内容分开

| 内容 | 归属 |
|---|---|
| 源码中的声明、表达式和位置 | 工具事实 |
| 在指定模型下计算的依赖或匹配 | 分析关系，同时保存前提和缺口 |
| 业务对象、边界、角色及环境的解释 | 宿主版本化上下文；模型解释需标明依据 |
| 假设、裁决、漏洞与处理状态 | 宿主安全平台，不由本工具自动写入 |

覆盖不足和执行失败不等于反证。工具不负责把无法判定的命题强制二分类，也不负责决定平台的报告门槛。

## 复用边界

保留 `internal/cbm/` 的解析运行时和语法库、`src/foundation/` 的必要组件以及 `vendored/yyjson/`。`security/` 使用独立构建。当前不拆仓库，不为目录外观改写解析器、工具名称或分析身份。

未来的资源操作、更多风险模型或语义图应复用这套证据契约。未合入的本地候选不能写进当前工具能力表，见[交付状态](development/status.md)。
