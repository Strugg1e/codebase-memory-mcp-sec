# 普通实参的受控 Java 对照

这是本次产品完善中独立编写的参考实验，不是原始 `0.15.0-dev` 候选文件或历史结果的恢复。仅编译并执行工具仓库中的固定样例，不能把任意被审计项目作为输入。

## 运行

先从仓库根目录构建可信分析器。实验需要 `javac`、`java` 和 POSIX 管道；未安装时明确失败，不算跳过成功。

```sh
make -f Makefile.security
python3 tests/java-argument-reference/compare.py --mcp build/security/cbm-security-mcp
```

脚本使用 [普通实参回放](../../security/demo_arguments.py)中的三份固定源码和本目录的 `ArgumentReference.java`。每个场景单独写入临时目录，关闭注解处理，编译和运行后清理。不接收项目目录或待执行的外部源码；设置了外部 Java 选项或 CLASSPATH 时拒绝运行。

## 检查什么

| 场景 | 五次运行预期返回值 | 静态形参来源 |
|---|---|---|
| 直接传参 | 100、100、101、100、101 | tenant |
| 中间调用换位 | 10、11、10、-1、-1 | id |
| 常量覆盖 | 0、0、0、0、0 | 不保留旧形参依赖 |
| 已知与未知返回并存 | 100、100、101、777、777 | tenant，且保留未知返回 |

输入依次为 `(10,100)`、`(11,100)`、`(10,101)`、`(-1,100)`、`(-1,101)`。前面三次在同一分支内单独改变一个参数，用于检查已观测到的数据变化是否被静态来源包含；后两次仅检查固定分支样例的运行值。参考输出同时保存样例字节哈希、静态未知项和源码引用计数。

分析快照不包含 Recorder 和 External 的实现；它们仅供参考运行使用。根目标实现缺失不应阻止调查已提供的实参，外部返回仍应保持未知。实际返回 777 不得被反向写入分析结果或当成净化证明。

## 不能证明什么

四个场景、二十次求值不是完整 Java 语义、所有路径、隐式控制依赖、运行时调用图或漏洞判定证明。没有观察到值变化，不证明参数对所有输入均无影响。独立 Java 对照是单独命令，不纳入普通安全专项的数量，也不自动改变现有远程 CI 工作流或跨平台支持声明。
