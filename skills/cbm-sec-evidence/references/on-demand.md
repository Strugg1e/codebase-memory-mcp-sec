# 按需使用，而不是增加一道扫描门槛

本说明适用于双循环、五阶段审计。两个领域循环由 Sulliu 管理；Codex/pi 自主完成任务内的阅读与取证；CBM Sec 只回答具体的程序问题。

## 调用前先明确问题

源码阅读已经足以回答时，可以不用 CBM Sec。需要批量定位或核对某项容易误读的关系时，再调用适合的工具。不为增加调用次数而调用，也不在每个阶段开头重复做全部分析。

第一次确实要调用时，核对本次快照、构建身份和能力；同一受信任会话中可以复用核对结果。快照或工具版本发生变化必须重新核对。这个规则不取消各工具的参数与哈希校验。

| 阶段 | 适用的问题 | 不应该替代什么 |
|---|---|---|
| 侦查 | 入口、声明、具体调用的批量查询 | 全局应用理解；没有工具仍可读源码 |
| 威胁建模 | 某项关键程序关系是否有出处 | 角色、业务要求和信任边界的认定 |
| 漏洞假设 | 给一个疑点补代码位置或局部依据 | 不要求先取得完整源到点路径才允许提问 |
| 对抗性验证 | 参数是否被覆盖、模板怎样绑定、配置可能适用何处 | 命题的安全语义与最终成立/不成立裁决 |
| 报告 | 核对已有证据的位置和版本 | 重新扫描、补编证据或扩大影响 |

## 从便宜的动作开始

优先复用当前快照上已经存在的结果。工具查询应对准当前问题的文件、调用现场和参数。需要详细材料时使用返回的 full_request 展开，不默认给每个 worker 注入整图或历史聊天。

`inspect_operation_context(view="summary")` 只是输出较少，不等于只执行浅层分析。它仍计算底层操作关系。评测时，调用 summary 也应计入深层工具开销，不能仅按响应大小给它算作廉价查询。

## 失败不能变成安全结论

- 工具缺失、不支持或达到预算：保留原因，继续用允许的源码阅读和其他材料调查。
- 证据哈希或快照不符：拒用该份结果，不能将它重新标成低置信证据后继续引用。修复快照交接后再查。
- 找不到路径：只说明本次范围和模型中没有得到路径，不是命题被推翻。
- 找到路径：只支持对应的程序关系，不直接确认漏洞。

已有源码依据可以支持假设；CBM Sec 的编号、规则命中或图完成度不是假设准入条件。不要自动接管缺口队列、切换扫描范围、创建新 Agent 或强制执行目标。

这是一份工具使用指导，不是权限执行器。宿主仍负责工具开放范围、源码只读、网络限制、预算、版本锁及实际执行记录。不要从被审计仓库安装技能或钩子。
